# Operations and recovery

Correlate the S3 key and version with the Step Functions input. Use the execution ARN in the processor CloudWatch log group and compare the DynamoDB owner, status and output key. `bedrock_completed` and `textract_completed` carry the AWS API request ID. For metrics, use AWS/States `ExecutionsSucceeded`, `ExecutionsFailed`, `ExecutionsTimedOut` and `ExecutionTime`, and AWS/SQS `ApproximateNumberOfMessagesVisible`. Alarms cover failed/timed-out executions and visible messages on the delivery DLQ. They have no notification action configured.

- **Permanent review**. Check `task_error` for the reason. For unsupported, malformed, or inconsistent documents, correct the source and upload new bytes. Preserve evidence before deleting the review message.
- **Operational review**. Check for throttle, timeouts, missing permissions or failed storage. Recover the dependency, then use the original input and set a top-level `"reprocess": true` in a **new** Standard execution. Leave the original bucket, key and `version-id` intact. An accepted document stays accepted. If a claim is still PROCESSING or READY after abnormal termination, wait for `lease_until` before reprocessing. For a publish conflict, verify the S3 object and checkpoint before making any changes.
- **EventBridge delivery DLQ**. Review the message and message attributes for ARN and delivery error. Repair the rule/target role. Start the state machine manually with the original event body. Verify the new execution before removing the message. No queue consumer replays events automatically.
- **SQS review recording failure**. The workflow attempts a smaller fallback notification containing the execution ARN and failure class. If both sends fail or a workflow times out before its catch, use the failed execution/alarms and the DynamoDB lease to investigate. A queue message can be delivered more than once, so use the execution ARN to correlate.
- **Exhaustion fixture**. Capture evidence while injection is enabled. If you choose to demonstrate operator reprocessing, set the stack's `EnableDemoFailures` to `false` through the original deployment method, then replay the same saved event with `reprocess: true`. This adds model calls and is outside the eight-upload base estimate.

Use SQS **Send and receive messages → Poll for messages** to inspect messages. Polling temporarily hides received messages; leave evidence messages intact until you finish verification. Built-in Step Functions redrive resumes at the failed state and is unsuitable for the terminal `NeedsReview` Fail state in this workflow. Start a new execution as described above.
