# Security

Use synthetic documents only. The pipeline creates separate encrypted S3 buckets with public access blocked, encrypted DynamoDB and SQS, and short log retention. The Lambda role reads versions only under the input `incoming/` prefix, writes and reads validated output only under `validated/`, uses a single DynamoDB table, and invokes a configured foundation model in the deployed region. Textract DetectDocumentText receives bytes and requires `Resource: "*"`. EventBridge has a role to start the one workflow. Its dead-letter queue policy allows this specific rule. The workflow role can invoke its processor and send to its review queue.

The prompt treats uploaded text as data. Strict parsing and arithmetic reject impossible output; plausible misread values can pass. Restrict artifact bucket writes and access to the acceptance report, S3 outputs, execution histories, DynamoDB candidate, SQS messages, and logs. Logs carry document IDs, execution ARNs, request IDs and tokens. Execution histories and review messages contain source object paths. Avoid placing personal information in filenames. Use named roles or IAM Identity Center and do not write long-lived credentials to configuration or logs. Leave demo failure injection disabled outside this exercise. For a real financial system, design human approval, retention, audit controls and access review before handling real data.
